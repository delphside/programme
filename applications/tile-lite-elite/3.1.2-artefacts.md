# 3.1.2 Tile Lite Elite artefacts

Tile Lite Elite's artefact register, in two parts: its artefacts by route, and
everything under change control that leaves no trace in git:
files on the production host, resources in Oracle Cloud, objects in GitHub, and
records held by services we do not run. For these, this file is the only
record, so entries carry enough to recreate them. Each artefact's route is in
[Artefacts by route](#artefacts-by-route) and, for these, the *route* column.

## Artefacts by route

Every artefact of Tile Lite Elite, in the repository or outside it, falls under
one route. The rule is [1.2 §2.15](../../docs/1.2-change-lifecycle.md#route); this is its
answer here. The artefacts outside the repository are listed one by one below.

| route | Tile Lite Elite's artefacts |
| --- | --- |
| Production Release | everything built into the image: `crates/**`, the word lists, `Caddyfile`, `Dockerfile`, `docker-compose.yml`; on the production host, files under `/opt/tile-lite-elite/`, the systemd units and the packages we install. Deployed by `deploy.sh` |
| Application Tooling and Docs | the scripts in `scripts/develop/`, `deliver/`, `operate/` and `measure/`, except what is installed on the production host; `ci.yml`, `e2e/**`, `.cargo/audit.toml` |
| Programme Tooling and Docs | the programme repository's scripts, git hooks and Claude hooks; `docs.yml` and the other workflows, the documents `documents.py` classes as programme |
| Other | the OCI console, GitHub settings, preview and rehearsal deploys |

"The production host" is the Oracle VM: its packages, its Docker daemon, and
the image's packages are ours; the hypervisor is not. `wordlist-tools` and
`scripts/develop/mkfavicon.py` are generators with a human step, so they are
Application Tooling and Docs. `.cargo/audit.toml` configures `cargo audit`
only; `.cargo/config.toml` would change the bytes and would be a release.

**The rule in executable form is the technical profile's `ships.non_shipping`**
in
[`programme.toml`](https://github.com/delphside/tile-lite-elite/blob/main/programme.toml)
at the application's root: the paths that do not ship, which is the stable
list, as regular expressions matched from the start of a path. The pre-commit
hook, `deploy.sh`, `verify.sh` and CI ask it through
`programme/scripts/board/board-shipping.py`; `shipping.py` applies it and holds
no path. What counts as a version-only bump is the profile's `versions.bump`.
This section is the authority for what belongs in the list. A commit touching
any image path is an image change, whatever else it touches.

## The production host

Verified on the VM, 2026-08-21.

| artefact | route | what it is | why it is not in the repository |
| --- | --- | --- | --- |
| `production:~/tile-lite-elite/docker-compose.yml` | Production Release | the compose file the running stack uses | **copied there by `deploy.sh`** from the repository — the copy is a deployment artefact, and the source of truth is in git |
| `production:~/tile-lite-elite/.env` | Other | secrets and per-host settings Compose reads: `RESEND_API_KEY`, `SITE_ADDRESS`, tuned rate limits | created by hand; holds secrets; `deploy.sh` never copies it ([4.3.4](https://github.com/delphside/tile-lite-elite/blob/main/docs/4.3.4-production-environment.md#container-topology)) |
| `production:~/.tile-lite-elite-backup-par` | Other | the write-only credential the nightly backup uses, mode `0600` | a secret ([4.3.4](https://github.com/delphside/tile-lite-elite/blob/main/docs/4.3.4-production-environment.md#the-nightly-copy-that-leaves-the-vm)) |
| `production:/opt/tile-lite-elite/` | Production Release | copies of `scripts/operate/backup-to-oci.sh`, `scripts/operate/check-log-hygiene-nightly.sh`, `scripts/operate/check-log-hygiene.py` and `docs/4.4.7-log-events.md`, which the nightly jobs run | **copied by hand by the delivery that changes them**: there is no checkout on the host, and nothing re-copies them, so a change to any of the four that is not re-copied leaves the host running the old version (#174) |
| `production:/etc/systemd/system/tile-lite-elite-{backup,log-check}.{service,timer}` | Production Release | the two nightly jobs and their timers, from `scripts/operate/systemd/` | installed by hand, like the files above |
| `production:~/tile-lite-elite/snapshots/` | Other | pre-deploy database snapshots, newest five kept | data, created by `deploy.sh` |
| `artifacts/<sha>.tar.gz` | Other | the built images for one commit, with a `.sha256` beside it. Newest five kept | **a cache, not a record.** Git-ignored, created by `deploy.sh`, shared by rehearsal and production so both load the same bytes (#214). Losing one costs a rebuild of that commit |
| `production:/etc/systemd/journald.conf.d/50-cap.conf` | Other | `SystemMaxUse=50M`, `RuntimeMaxUse=16M`, written 2026-07-30. Its `SystemMaxUse` is overridden by the file below; its `RuntimeMaxUse` is in force | applied by hand; journald is not on defaults |
| `production:/etc/systemd/journald.conf.d/zz-tile-lite-elite.conf` | Other | `SystemMaxUse=100M`, `MaxRetentionSec=7d` (#174). Named to sort last, since journald applies these files in name order and a later value wins | applied by hand |
| `production:` docker volumes `tile-lite-elite-data`, `-caddy-data`, `-caddy-config` | Other | the database, and Caddy's certificates and state | created by Docker, and the first is the only irreplaceable thing on the machine |
| `production:` iptables `INPUT` chain | Other | accepts established, ICMP, loopback and **22 only**; rejects the rest | applied by hand |

Ports 80 and 443 are not in the `INPUT` chain: Docker publishes them through
its own `DOCKER` chain in the `nat` table, which bypasses `INPUT`.

The compose file on the host is a copy. An edit there changes what runs until
the next deploy overwrites it.

## Exit statuses in Tile Lite Elite's scripts

The scheme is [1.2 §2.13](../../docs/1.2-change-lifecycle.md#what-a-scripts-exit-status-means) (D46, delphside/tile-lite-elite#327). `ci-status.sh` and `check-release-version.sh` return `2` when they could not judge; `deploy.sh` returns `3` when production is live and a step after the swap failed. Scripts report through the log events in
[4.4.7](https://github.com/delphside/tile-lite-elite/blob/main/docs/4.4.7-log-events.md).

## Not yet recorded

Named rather than omitted, because an incomplete list that says where it is
incomplete is useful and one that pretends to be complete is not.

- **DNS** for `tileliteelite.com` and `rehearsal.tileliteelite.com` — the records
  exist and where they are held has not been written down here
- **the rehearsal environment's host artefacts** — the same shape as production's
  and not yet inventoried
- **the rehearsal access gate** from #240 — the `Caddyfile` matcher is in the
  repository and ships with the image, but the key itself lives in
  `rehearsal:~/tile-lite-elite/.env`, written by `scripts/deliver/rehearsal-access.sh`

## What counts as an artefact here

The rule is [1.2 §2.13](../../docs/1.2-change-lifecycle.md#what-counts-as-an-artefact-and-when-an-entry-appears). `deploy.sh` and `programme/.claude/hooks/turn-check.sh` are artefacts. Test code (`scripts/tests/`, the programme repository's `scripts/board/tests/` and `scripts/tests/`, `crates/*/examples/`) is not.
