# 3.1.5 Tile Lite Elite role holders

Who holds the roles for Tile Lite Elite that the programme-wide record,
[2.2](../../records/2.2-roles.md), does not hold; the owner is among those 2.2
holds. The roles are defined in
[1.7](../../docs/1.7-roles-and-responsibilities.md); the form is
[the template](../../docs/templates/role-assignment.md). Workstream names are
those of [3.1.4](3.1.4-workstreams.md).

## Who holds each role here

| Role | Held by |
| --- | --- |
| design authority | the owner threads below, each for the workstreams listed; Process Definition and Programme Tooling are the programme authority's, in [2.2](../../records/2.2-roles.md) |
| release manager, environments manager | the service owner, locally |
| security | this application's controls: the accounts & security authority |

| Owner thread | Design authority for | Kind | Runs |
| --- | --- | --- | --- |
| game architecture authority | TLE: Application Architecture, TLE: Client; the end-to-end design, while technical leads build each delphside/tile-lite-elite#71 package | permanent | cloud |
| service owner | Operations & Infrastructure, TLE: Delivery Tooling, Capacity & Performance, TLE: Client Distribution | permanent | local, on the owner's machine |
| rules & engine authority | TLE: Game Rules, TLE: Engine Player | on call | cloud |
| accounts & security authority | TLE: Security & Access | on call | cloud |

An on-call authority is defined by its documents and, once written, a
short skill saying what it signs off and what it defers to:

| Authority | Its documents |
| --- | --- |
| rules & engine authority | [4.2.1](https://github.com/delphside/tile-lite-elite/blob/main/docs/4.2.1-rules-engine.md), [4.2.2](https://github.com/delphside/tile-lite-elite/blob/main/docs/4.2.2-rules-engine-implementation.md), [4.2.8](https://github.com/delphside/tile-lite-elite/blob/main/docs/4.2.8-engine-performance.md), [4.3.5](https://github.com/delphside/tile-lite-elite/blob/main/docs/4.3.5-word-lists-and-dictionaries.md) |
| accounts & security authority | [4.2.5](https://github.com/delphside/tile-lite-elite/blob/main/docs/4.2.5-authentication.md), [4.2.6](https://github.com/delphside/tile-lite-elite/blob/main/docs/4.2.6-authentication-examples.md), [4.2.7](https://github.com/delphside/tile-lite-elite/blob/main/docs/4.2.7-authentication-and-invitations.md) |

The demand manager makes an on-call authority permanent when its area gets
busy.
