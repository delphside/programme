# 3.1.5 Tile Lite Elite role holders

Who holds the roles for Tile Lite Elite that the programme-wide record (the owner among them),
[2.2](../../records/2.2-roles.md), does not hold. The roles are defined in
[1.7](../../docs/1.7-roles-and-responsibilities.md); the form is
[the template](../../docs/templates/role-assignment.md). Workstream names are those of
[3.1.4](3.1.4-workstreams.md).

| role | held by |
| --- | --- |
| design authority | the owner threads below, each for the workstreams listed; Process Definition and Programme Tooling are the programme authority's, in [2.2](../../records/2.2-roles.md) |
| release manager, environments manager | the service owner, locally |
| security | this application's controls: the accounts & security authority |

| owner thread | design authority for | kind | runs |
| --- | --- | --- | --- |
| game architecture authority | TLE: Application Architecture, TLE: Client; the end-to-end design, while technical leads build each #71 package | permanent | cloud |
| service owner | Operations & Infrastructure, TLE: Delivery Tooling, Capacity & Performance, TLE: Client Distribution | permanent | local, on the owner's machine |
| rules & engine authority | TLE: Game Rules, TLE: Engine Player | on call | cloud |
| accounts & security authority | TLE: Security & Access | on call | cloud |

An on-call authority is defined by its document sections (Tile Lite Elite's
[4.2.1](https://github.com/delphside/tile-lite-elite/blob/main/docs/4.2.1-rules-engine.md) and
[4.2.2](https://github.com/delphside/tile-lite-elite/blob/main/docs/4.2.2-rules-engine-implementation.md);
[4.2.5 to 4.2.7](https://github.com/delphside/tile-lite-elite/blob/main/docs/4.2.5-authentication.md)) and, once written, a short skill saying what it signs off and
what it defers to. It becomes permanent when its area gets busy.
