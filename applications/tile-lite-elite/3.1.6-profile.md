# 3.1.6 Tile Lite Elite profile

A multiplayer word-tile game, in production. What the programme's processes
need to know about it is below; the form is
[the template](../../docs/templates/application-profile.md). The technical
profile, how a version is read, what ships and the commands, is
`programme.toml` at the root of
[its repository](https://github.com/delphside/tile-lite-elite/blob/main/programme.toml).

## Identity

| field | value |
| --- | --- |
| name | Tile Lite Elite |
| code | `TLE` |
| number | `1` |
| repository | `delphside/tile-lite-elite` |
| board view | Tile Lite Elite |
| document range | `4` |

## Versioning

| field | value |
| --- | --- |
| scheme | `semver` |
| commit stamp | `app <X.Y.Z> api <M.N>: <subject>` |

## Environments

In the order a change reaches them. Where a URL is not fixed, the technical
profile's `environments` key gives a default, or the script to source and the variable it sets.

| environment | purpose | URL |
| --- | --- | --- |
| preview | what you last looked at | not fixed: a developer's own machine; the technical profile gives the default |
| rehearsal | what the release gate checks | not fixed: the host is read from the script the technical profile names |
| production | what users have | `https://tileliteelite.com` |

## Routes

The routes its deliveries take, from [1.2](../../docs/1.2-change-lifecycle.md) §2.15;
the artefacts under each are in [3.1.2](3.1.2-artefacts.md#artefacts-by-route).

| route | how a change on it reaches its users |
| --- | --- |
| Production Release | when the release is deployed to production |
| Application Tooling and Docs | when its branch merges and is pushed to `origin/main` |
| Programme Tooling and Docs | when it is pushed to `origin/main` |
| Other | when somebody applies it |
