# 3.3.6 Infrastructure profile

What the applications share: their hosts, the networking in front of them and
host security. What the programme's processes need to know about it is below;
the form is [the template](../../docs/templates/application-profile.md).
The technical profile is `app-profile.toml` at the root of
[its repository](https://github.com/delphside/infrastructure/blob/main/app-profile.toml);
the hosts are listed in each hosted application's own.

## Environments

In the order a change reaches them. Infrastructure has none of its own beyond
the hosts it serves, which are each application's.

| Environment | Purpose | URL |
| --- | --- | --- |
| hosts | each application's pair of hosts, the pair first and then production, listed in [6.3.4](https://github.com/delphside/infrastructure/blob/main/docs/6.3.4-hosts.md#the-hosts) | not fixed: private, reached over SSH |

## Routes

The routes its deliveries take, from
[1.2 §2.15](../../docs/1.2-change-lifecycle.md#route); the artefacts under each
are in [3.3.2](3.3.2-artefacts.md#artefacts-by-route).

| Route | When a change on it reaches its users |
| --- | --- |
| Other | when it is applied to the host or console: host maintenance, the network, DNS and the Oracle account |
| Docs and Programme Tooling | when it is pushed to `origin/main` |

## Target architecture

| | Target |
| --- | --- |
| who | the infrastructure application, owned by Operations & Infrastructure, with its own repository `delphside/infrastructure`; its issues are on the programme board |
| what it holds | the hosts, networking (domain, DNS, ports, firewall), host security and keeping the hosts current |
| what it serves | each application, which depends on it only as its host; no application depends on another, and no host is shared |
| how it changes | a host or network change is its delivery, made as [6.3.4](https://github.com/delphside/infrastructure/blob/main/docs/6.3.4-hosts.md#making-a-host-change) says; afterwards the application on that host runs its own verification |
| how it coordinates | a project that affects an application, by a change or only by its regression testing, raises a requirement in that application's repository and coordinates the work |

Capacity is each application's plan, which carries its own host
([3.3.3](3.3.3-capacity-plan/README.md)).
