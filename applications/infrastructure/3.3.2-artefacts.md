# 3.3.2 Infrastructure artefacts

Infrastructure's artefact register, in two parts: its artefacts by route, and
everything under change control that leaves no trace in git: the hosts, the
network and the domain in Oracle Cloud Infrastructure (OCI) and at GoDaddy, the
SSH keys, and the Oracle account. This file is the only record of the second, so
each entry carries enough to recreate it, or links to where
[6.3.4](https://github.com/delphside/infrastructure/blob/main/docs/6.3.4-hosts.md)
holds the detail.

A host's address is held in the owner's SSH configuration under its alias and
is not recorded: the repositories are public. A host is named here by its `ssh`
alias, followed by a colon and the path, because *production* alone does not say
which application's.

## Artefacts by route

The rule is [1.2 §2.15](../../docs/1.2-change-lifecycle.md#route); this is its
answer here.

| Route | Infrastructure's artefacts |
| --- | --- |
| Production Release | none: Infrastructure ships no image. What an application installs on its host (its scripts, systemd units and the packages it needs) is that application's release, and is in its own register |
| Application Tooling | none yet: the repository has no scripts |
| Docs and Programme Tooling | the `6.x` documents in `delphside/infrastructure`, and anything else in that repository |
| Other | the hosts, the OCI console (the network and the account), DNS at GoDaddy and the SSH keys. The hosts' maintenance (OS packages, the container runtime, the kernel, reboots, journald caps and firewall rules) is Infrastructure's delivery, numbered by date ([1.2 §2.15](../../docs/1.2-change-lifecycle.md#host-maintenance-is-the-infrastructure-applications)), and marked `Other, host maintenance` below |

The cases a reader might misplace:

- The packages an application needs on its host, and the image's packages, are
  that application's Production Release. The hypervisor is Oracle's.
- An application's own console resources (its buckets, alarms, registry and
  their policies) are its register's, not this one.

| `tile-lite-elite:/etc/systemd/journald.conf.d/zz-tile-lite-elite.conf` | Other, host maintenance | `SystemMaxUse=100M`, `MaxRetentionSec=7d`. Named to sort last, since journald applies these files in name order and a later value wins | applied by hand |

Docker publishes ports 80 and 443 through its own `DOCKER` chain in the `nat`
table, which bypasses `INPUT`, so on a host that publishes them the subnet's
security list is what decides who reaches them.

## SSH keys

Each host's key is its own, and its public half is on the host in
`~/.ssh/authorized_keys`. The private halves are in the owner's `~/.ssh`, and
never in a repository.

| Artefact | Route | What it is |
| --- | --- | --- |
| `~/.ssh/oracle_tile_lite_elite` | Other | `tile-lite-elite`'s key |
| `~/.ssh/oracle_tile_lite_elite_rehearsal` | Other | `tile-lite-elite-rehearsal`'s key |
| `~/.ssh/oracle_dark_portal` | Other | `dark-portal`'s key |
| `~/.ssh/oracle_dark_portal_nonprod` | Other | `dark-portal-nonprod`'s key |
