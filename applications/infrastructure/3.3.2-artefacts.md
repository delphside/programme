# 3.3.2 Infrastructure artefacts

Infrastructure's artefact register holds two things:

- its artefacts by route
- everything under change control that leaves no trace in git: the hosts, the
  network and the domain in Oracle Cloud Infrastructure (OCI) and at GoDaddy,
  the SSH keys and the Oracle account

This file is the only record of the second, so each entry carries enough to
recreate it, or links to where
[6.3.4](https://github.com/delphside/infrastructure/blob/main/docs/6.3.4-hosts.md)
holds the detail.

No host address is recorded
([6.3.4](https://github.com/delphside/infrastructure/blob/main/docs/6.3.4-hosts.md)).
A host is named as
[1.2 §2.13](../../docs/1.2-change-lifecycle.md#213-the-impacted-artefacts-and-why-they-are-listed-early)
says: its role, then the absolute path. Within one application's register the
role alone is enough (`non-production:/srv/dp`, as Dark Portal's 3.2.2 writes
it); this register spans applications, so it qualifies the role with the
application, as `Dark Portal non-production:/srv/dp` and
`Tile Lite Elite production:/etc/…`. The roles and the `ssh` aliases are in
the table in
[6.3.4](https://github.com/delphside/infrastructure/blob/main/docs/6.3.4-hosts.md#the-hosts).

## Artefacts by route

The rule is [1.2 §2.15](../../docs/1.2-change-lifecycle.md#route); this is its
answer here.

| Route | Infrastructure's artefacts |
| --- | --- |
| Production Release | none: Infrastructure ships no image. What an application installs on its host is that application's release, and is in its own register |
| Application Tooling | none yet: the repository has no scripts |
| Docs and Programme Tooling | the `6.x` documents in `delphside/infrastructure`, and anything else in that repository |
| Other | the hosts, the OCI console (the network and the account), DNS at GoDaddy and the SSH keys. The hosts' maintenance is Infrastructure's delivery, numbered by date ([1.2 §2.15](../../docs/1.2-change-lifecycle.md#host-maintenance-is-the-infrastructure-applications)), and marked `Other, host maintenance` in [*The hosts*](#the-hosts) |

The cases a reader might misplace:

- The image's packages are the Production Release of the application that
  builds the image. The hypervisor is Oracle's.
- An application's own console resources (its buckets, alarms, registry and
  their policies) belong to that application's register.

Docker publishes ports 80 and 443 through its own `DOCKER` chain in the `nat`
table, which bypasses `INPUT`, so on a host that publishes them the subnet's
security list is what decides who reaches them.

## SSH keys

Each host's key is its own, and its public half is on the host in
`~/.ssh/authorized_keys`. The private halves are in the owner's `~/.ssh`, and
never in a repository.

| Artefact | Route | What it is |
| --- | --- | --- |
| `~/.ssh/oracle_tile_lite_elite` | Other | `tile-lite-elite`'s key |
| `~/.ssh/oracle_tile_lite_elite_rehearsal` | Other | `tile-lite-elite-rehearsal`'s key |
| `~/.ssh/oracle_dark_portal` | Other | `dark-portal`'s key |
| `~/.ssh/oracle_dark_portal_nonprod` | Other | `dark-portal-nonprod`'s key |
