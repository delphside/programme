# 3.3.4 Infrastructure's workstreams

Infrastructure's workstream register. What a workstream is, and the generic
workstreams, are [1.3](../../docs/1.3-workstreams.md); the form is
the [workstream-register template](../../docs/templates/workstream-register.md).
The infrastructure repository has no commits yet, so its workstreams' artefacts
are outside its repository, and any files about them follow with the
repository's first commits.

## This application's workstreams

| Workstream | Instance of | Owns |
| --- | --- | --- |
| Operations & Infrastructure | the same | the hosts, networking (the domain name, DNS, ports and firewall), host security, and keeping the hosts current |
| Capacity & Performance | the same | whether each host will still fit what runs on it: the hosts' capacity plan |

Both are programme-wide workstreams, so they take no prefix
([1.3 *How the names are written*](../../docs/1.3-workstreams.md#how-the-names-are-written)).

The generic workstreams with no instance here:

| Workstream | Why |
| --- | --- |
| Application Architecture, Client, Client Distribution, domain workstreams | Infrastructure serves the applications only as their host. |
| Security & Access | Infrastructure has no accounts or identity of its own. |
| Delivery Tooling | Operations & Infrastructure owns the host scripts ([1.1](../../docs/1.1-programme-tooling.md#two-kinds-of-tooling)); a host change is made by hand and is a dated delivery. Claude revisits this at the repository's first commit. |
| Process Definition and Programme Tooling | They manage the programme itself and are in [2.6](../../records/2.6-workstreams.md). |

### Operations & Infrastructure

The hosts and what reaches them. It is one workstream across every
application, because each application's host is run the same way.

#### The artefacts Operations & Infrastructure owns

Each is to be registered in 3.3.2, which is not yet written.

| Artefact | For |
| --- | --- |
| the hosts | the virtual machines each application runs on |
| the domain name, DNS records and the subnet's security list | networking, ports and the firewall |
| the SSH keys and the Oracle account | access to the hosts |

#### Where the line falls between Operations & Infrastructure and a hosted application

Infrastructure owns the host and what it exposes. The application on it owns
what runs there and verifies itself after a host change. A project that
affects a hosted application raises a requirement in that application's
repository ([the design](3.3.7-changes/489-shared-infrastructure/489-design.md#the-target)).
