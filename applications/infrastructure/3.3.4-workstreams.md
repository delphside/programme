# 3.3.4 Infrastructure's workstreams

Infrastructure's workstream register. What a workstream is, and the generic
workstreams, are [1.3](../../docs/1.3-workstreams.md); the form is
the [workstream-register template](../../docs/templates/workstream-register.md).
The infrastructure repository has no commits yet, so the workstreams have no
`###` section yet: their artefacts are outside its repository, and any files
about them follow with the repository's first commits.

## This application's workstreams

| Workstream | Instance of | Owns |
| --- | --- | --- |
| Operations & Infrastructure | the same | the hosts, networking (the domain name, DNS, ports and firewall), host security, and keeping the hosts current |
| Capacity & Performance | the same | whether each host will still fit what runs on it: the hosts' capacity plan |

Both are programme-wide workstreams, so they take no prefix
([1.3 *How the names are written*](../../docs/1.3-workstreams.md#how-the-names-are-written)).

The generic workstreams with no instance here:

| Workstream | Why |
| --- | --- |
| Application Architecture, Client, Client Distribution, domain workstreams | Infrastructure serves the applications only as their host. |
| Security & Access | Infrastructure has no accounts or identity of its own. |
| Delivery Tooling | A host change is made by hand and recorded as a dated delivery. |
| Process Definition and Programme Tooling | They manage the programme itself and are in [2.6](../../records/2.6-workstreams.md). |
