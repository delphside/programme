# 3.2.4 Dark Portal's workstreams

Dark Portal's workstream register: each workstream an instance of a generic
one, or a domain workstream. What a workstream is, and the generic workstreams,
are [1.3](../../docs/1.3-workstreams.md); the form is
[the template](../../docs/templates/workstream-register.md). The code does not
exist yet, so each workstream names what it will own; paths, and each
workstream's artefacts table, follow with the code. The other four generic
instances have no section of their own until a boundary needs one.

## This application's workstreams

| Workstream | instance of | owns |
| --- | --- | --- |
| Market Data | Application Architecture | the Blizzard API client, the hourly auction snapshots, game data (items, recipes, professions), the stored data and its model |
| Market Analysis | a domain workstream | prices, crafting margins with flipping included (buying an item to resell it, a recipe whose input and output are the same item), risk indicators and trading strategies |
| CLI | Client | what the owner sees and types: the command-line tool, and any later notebook or GUI |
| Operations & Infrastructure | the same | the running collector, watched and recovered, and the Blizzard API credentials; the host is [Infrastructure's](../infrastructure/README.md) |
| Delivery Tooling | the same | this application's machinery from a commit to a running environment |
| Capacity Planning | Capacity & Performance | whether Dark Portal's memory share, its Blizzard API quota and its storage growth will still fit, and how fast the analysis runs |

Security & Access has no instance: the owner is the only user and reaches the
service privately
([489 design](../infrastructure/3.3.7-changes/489-shared-infrastructure/489-design.md#how-the-second-application-is-reached-privately)),
so there are no accounts to manage. The API credentials sit with Operations &
Infrastructure.

Process Definition and Programme Tooling manage the programme itself, not this
application, and are in [2.6](../../records/2.6-workstreams.md).

### Market Data

Getting the market and game data in, and keeping it in a shape the analysis can
use. It is one capability because what is collected, how often and how it is
stored are decided together.

#### Market Data and Market Analysis

| | owner |
| --- | --- |
| a snapshot, an item, a recipe as data: what is stored and for how long | Market Data |
| what a price, margin or risk means and how it is worked out | Market Analysis |

### Market Analysis

Turning prices into decisions: current price and history, crafting margins,
risk, and the strategies built on them. A domain workstream because it has
mechanisms of its own (pricing, margins, risk, strategies) and changes with how
the owner trades, not with how data arrives.
