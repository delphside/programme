# 3.2.4 Dark Portal's workstreams

Dark Portal's workstream register: each workstream an instance of a generic
one, or a domain workstream. What a workstream is, and the generic workstreams,
are [1.3](../../docs/1.3-workstreams.md); the programme's own are in
[2.6](../../records/2.6-workstreams.md); the form is
[the template](../../docs/templates/workstream-register.md). The collector's
code does not exist yet, so each workstream names what it owns; paths, and each
workstream's artefacts table, follow with the code. Only Application
Architecture and Market Analysis have a section of their own; whoever finds a
boundary for another adds one.

## This application's workstreams

| Workstream | Instance of | Owns |
| --- | --- | --- |
| DP: Application Architecture | Application Architecture | the Blizzard API client, the hourly auction snapshots, game data (items, recipes, professions), the stored data and its model, and the restore after a lost host |
| DP: Market Analysis | a domain workstream | prices, crafting margins, risk indicators and trading strategies |
| DP: Client | Client | what the owner sees and types: the command-line tool and the notebook, and later the in-game add-on and the opportunity alerts |
| Operations & Infrastructure | the same | the running collector (which fetches the auction house data), watched and recovered, and the Blizzard API credentials; the hosts are [Infrastructure's](../infrastructure/README.md) |
| DP: Delivery Tooling | Delivery Tooling | this application's machinery from a commit to a running environment |
| Capacity & Performance | the same | whether Dark Portal's memory, its Blizzard API quota and its storage growth still fit their ceilings, how fast the analysis runs, and `sizing/` in [Dark Portal's repository](https://github.com/delphside/dark-portal/tree/main/sizing) |

### Application Architecture

Getting the market and game data in, and keeping it in a shape the analysis can
use. It is one workstream because what is collected, how often and how it is
stored are decided together.

#### The data is Application Architecture's, its meaning Market Analysis's

| Subject | Owner |
| --- | --- |
| a snapshot, an item, a recipe as data: what is stored and for how long | DP: Application Architecture |
| the transforms from *bronze* (the source snapshots) to *silver* (enriched listings and events) and *gold* (the summaries), the inferred events included | DP: Application Architecture; the first version is in delphside/dark-portal#7 *#5 WP B Del 2 of 5: consumable profiles* |
| what a price, margin or risk means and how it is worked out | DP: Market Analysis |

#### The restore here, the running collector in Operations & Infrastructure

The restore after a lost host, delphside/dark-portal#38 *Restore Dark Portal
after a lost host*, is Application Architecture's, because what must be
restored is the stored data and its model. Operations & Infrastructure owns
the running collector that writes it.

### Market Analysis

Turning prices into decisions: current price and history, crafting margins,
risk and the strategies built on them. A domain workstream because it has
mechanisms of its own (pricing, margins, risk and strategies) and changes with
how the owner trades. Its crafting margins include *flipping*: crafting a
recipe whose input and output are the same item.
