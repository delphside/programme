# 3.2.2 Dark Portal artefacts

Dark Portal's artefact register, in two parts: its artefacts by route, and
everything under change control that leaves no trace in git. For the second
part this file is the only record, so each entry carries enough to recreate it.

## Artefacts by route

The rule is [1.2 §2.15](../../docs/1.2-change-lifecycle.md#route); this is its
answer here.

| Route | Dark Portal's artefacts |
| --- | --- |
| Production Release | none yet: the collector's image (the collector fetches the auction house data each hour), and whatever its deliveries install on the host |
| Application Tooling | none yet: the scripts that build, deploy, operate and measure it |
| Docs and Programme Tooling | the `5.x` documents changed on their own, and anything else in `delphside/dark-portal` |
| Other | its own Oracle Cloud (OCI) resources and GitHub settings. The host and its maintenance (its base packages, the container runtime, reboots) are [Infrastructure's](../infrastructure/3.3.2-artefacts.md), a delivery numbered by date ([1.2 §2.15](../../docs/1.2-change-lifecycle.md#host-maintenance-is-the-infrastructure-applications)) |

## The host

The host is Infrastructure's, and is in
[Infrastructure's artefact register](../infrastructure/3.3.2-artefacts.md): the
VMs, their Docker, base packages, the network and the Oracle budget. It is
pre-production while Dark Portal is built: one user, reached by SSH.

The host's address is not recorded here
([6.3.4](https://github.com/delphside/infrastructure/blob/main/docs/6.3.4-hosts.md)).
