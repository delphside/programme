# 2.2 Programme role holders

Who holds the programme-wide roles. The roles are defined in
[1.7](../docs/1.7-roles-and-responsibilities.md); each application's own
holders are its `3.n.5`, listed in [2.1](2.1-applications.md). The form is the
[role-assignment template](../docs/templates/role-assignment.md).

An *owner thread* is the thread that holds an area's design authority
([1.7](../docs/1.7-roles-and-responsibilities.md#demand-manager)).

## Who holds each role here

| Role | Held by |
| --- | --- |
| owner | Stephen, for the programme and for every application in it |
| design authority | the programme authority for the programme's own workstreams; for each application's workstreams, the owner threads in its `3.n.5`, and the service owner below |
| technical lead | a thread per project or work package, for its life |
| demand manager | the coordinator; each area's owner thread triages its own area |
| release manager, environments manager | each application's `3.n.5` |
| test manager | an on-call thread, never the one that built the change |
| librarian | the programme authority |
| security | policy: the programme authority; an application's controls: the holder in its `3.n.5` |

| Owner thread | Design authority for | Kind | Runs |
| --- | --- | --- | --- |
| programme authority | Process Definition, Programme Tooling | permanent | cloud |
| service owner | Operations & Infrastructure, Capacity & Performance: one thread across every application ([1.3](../docs/1.3-workstreams.md#generic-workstreams)); each application's `3.n.5` adds its own workstreams | permanent | local, on the owner's machine |
| coordinator | none | permanent | cloud |
| test manager | none | on call | cloud |

**The coordinator starts the test manager** when:

- a project's or work package's test approach is ready for approval;
- a release's regression run on rehearsal has finished;
- a pull request changes the
  [dependency update project template](../docs/templates/dependency-update-project.md);
- a dependency update row needs a test the template does not list.

The test manager closes once it has answered.
