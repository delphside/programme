# 2.1 Applications

The applications the programme manages. The index *n* is the number in each
application's record numbers, as [1.5](../docs/1.5-writing-documents.md)
sets out. The one programme board will show every repository's issues, with a
view per application; it is set up in delivery 1 of
delphside/tile-lite-elite#485, and until then the board is Tile Lite Elite's
([1.6](../docs/1.6-github-project-board.md)).

| n | code | application | repository | purpose | folder here | its own documents |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | TLE | Tile Lite Elite | `delphside/tile-lite-elite` | a multiplayer word-tile game: its server, web and desktop client, and the bot engine; in production | [`applications/tile-lite-elite/`](../applications/tile-lite-elite/README.md) | 4.x |
| 2 | DP | Dark Portal | `delphside/dark-portal` | an analysis tool for the World of Warcraft auction house; not started | [`applications/dark-portal/`](../applications/dark-portal/README.md) | 5.x |
| 3 | INF | Infrastructure | `delphside/infrastructure` | what the applications share: the hosts' capacity, networking and security; repository not yet created (delphside/tile-lite-elite#489) | [`applications/infrastructure/`](../applications/infrastructure/README.md) | 6.x |

A new application takes the next index, and so the next `3.n` and `(3+n).x`.

The code is the owner's prefix in a report's name (`TLE_CP_2026_09.md`). `PRG` is for programme-wide reports, so the weekly digests are `PRG_WD_<yyyy>_W<ww>.md`; the files written before this rule keep their names.
