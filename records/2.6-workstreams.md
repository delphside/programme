# 2.6 Programme workstreams

The programme's own workstreams, which manage the programme itself rather than
any application: Process Definition and Programme Tooling. They are generic
workstreams ([1.3](../docs/1.3-workstreams.md)) and belong to no application, so
their register is here and each application's `3.n.4` links to it. The form is
[the template](../docs/templates/workstream-register.md). File paths are in the
[Tile Lite Elite repository](https://github.com/delphside/tile-lite-elite) until
the programme's scripts move here.

## The programme's workstreams

| Workstream | owns |
| --- | --- |
| Process Definition | every process, and the documents that state it: `docs/1.2` to `1.5` and `1.7`, `CLAUDE.md`, `docs/templates/` |
| Programme Tooling | the board, the documentation gates, the git hooks, and Claude's tooling: `scripts/programme/`, `.githooks/`, `.claude/` |

## Process Definition

How the programme works: how a change is raised, classified, agreed, built,
tested, delivered and reviewed, the roles, and the documents that state it.
Each rule is kept separable from an application's answer to it.

### The artefacts Process Definition owns

| artefact | |
| --- | --- |
| `CLAUDE.md`, `AGENTS.md` | the one-page rules, and the guide for outside agents |
| `docs/1.2` to `1.5` and `1.7` | the lifecycle, the workstreams, the activities, how documents are written, the roles |
| Tile Lite Elite's `docs/4.3.3` §2.2.1 to §2.2.4 | the test strategy, until delphside/tile-lite-elite#427 gives it a home of its own |
| each application's `3.n.1` delivery log and `3.n.2` artefact register, and their templates | the records and their form, for Tile Lite Elite [3.1.1](../applications/tile-lite-elite/3.1.1-delivery-log.md) and [3.1.2](../applications/tile-lite-elite/3.1.2-artefacts.md) |
| [`2.5-changes/process-definition/glossary.md`](2.5-changes/process-definition/glossary.md) | D1 to D38; history, not added to |
| `docs/templates/`, `.github/ISSUE_TEMPLATE/` | the forms |

## Programme Tooling

The tooling the programme manages itself with: the board, the documentation
gates and the map, the digest and reports, the git hooks, and Claude's skills,
agents and hooks.

### The artefacts Programme Tooling owns

| artefact | |
| --- | --- |
| `scripts/programme/`, its tests, and `scripts/issue-mentions.sh` | the board model, the documentation gates, the reports |
| `docs/1.1`, `docs/1.6` | the programme's tooling, and the board's types, fields and the strings tooling matches |
| the issue types, fields and option values | what the board is built from |
| `.github/workflows/docs.yml` | the review workflow |
| `.githooks/` | the refusals at commit time |
| `.claude/` | Claude's skills, agents and hooks |
