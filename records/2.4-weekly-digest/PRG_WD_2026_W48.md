### From the issues closed this week

#### #421 MAIN PROJECT: Scripts sub-folders

A move wired to a local hook does not run for work merged on GitHub, so a check on "the next merge" should name how it merges. Folding delivery 3 into the repository split was cheaper than finishing a layout the split would undo.

The review is [`421-post-deployment-review.md`](https://github.com/delphside/programme/blob/main/applications/tile-lite-elite/3.1.7-changes/workstreams/delivery-tooling/421-scripts-sub-folders/421-post-deployment-review.md) (2026-11-16, delphside/programme#216).

*Conclusion, at the weekly review:* no action of its own: a local hook that does not run for work merged on GitHub is the same gap as the review record's, which the check on the pull request closes under `CI-3`.

#### #441 Sub-agents

A check on how often a practice is used needs the practice to leave a record. Where a prompt is the only artefact, the pull request's review record is the place to name its headings.

The review is [`441-post-deployment-review.md`](https://github.com/delphside/programme/blob/main/applications/tile-lite-elite/3.1.7-changes/workstreams/delivery-tooling/441-sub-agents/441-post-deployment-review.md) (2026-11-16, delphside/programme#216).

*Conclusion, at the weekly review:* initiative, `CI-3`: the review record's check on the pull request is where a practice's use is recorded and read.
